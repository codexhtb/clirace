# Product consolidation V1

Дата аудита: 2026-08-22. Этот документ фиксирует решения до реализации. Цель фазы — уменьшить продуктовый и технический шум без удаления пользовательских данных и без изменения правил действующих режимов.

## P0 — смысл продукта

- **Ranked MMR** (`user_ranked_stats.mmr`) — единственный соревновательный рейтинг. Он меняется только после завершённого Ranked-матча и влияет на Ranked matchmaking.
- **Practice score** (`user_ratings.rating`) — оценка результатов практики. Историческое имя столбца остаётся в БД; во внешнем API вводится `practiceScore`, старое `rating` временно сохраняется как deprecated alias.
- Quick Match и Private Battle не меняют MMR.
- `/rating` — канонический рейтинг. `/leaderboard` — legacy URL с постоянным redirect.

## P1 — основной путь пользователя

- `/play`: только индивидуальная практика и real-shell; небольшой secondary link ведёт в Online.
- `/online`: отдельный PvP-раздел с primary Quick Match и secondary Ranked/Private Battle.
- Настоящий shell — главный рабочий элемент real-shell задачи. Таймер практики показывает прошедшее время, а не создаёт ложное ощущение дедлайна.
- Профиль начинается с личности и компактного Ranked-статуса. Для пользователя без активности показывается понятный zero state, а не панель из нулей.
- Единый словарь: «Практика», «Оценка практики», `MMR`, «Задача дня», русские названия сложности и режимов.
- Один спокойный loading state; технические признаки инфраструктуры не используются как продуктовые бейджи.

## P2 — сокращение дублей

- Общие функции названий сложности, режима и статуса вынесены в один модуль.
- Ranked-статус отображает общий `RankBadge` в play/profile/rating/result там, где это помогает чтению.
- Очевидные тяжёлые страницы загружаются лениво. Battle и shell сохраняют существующие границы чанков.
- Polling Quick и Ranked сохраняет раздельные жизненные циклы: сценарии восстановления и ошибки отличаются, поэтому рискованное объединение хуков в этой фазе не выполняется.

## P3 — совместимость и уборка

- Схема БД не очищается: активные таблицы и исторические колонки остаются.
- Индексы Ranked, Battle, Learn и Learning Paths уже покрывают критические выборки; миграция индексов не требуется.
- Внутреннее Redis-поле `rating` в Ranked matchmaking остаётся без переименования: оно хранит MMR, но смена имени нарушила бы совместимость активных очередей/Lua-операций.
- E2E-аккаунты должны удаляться с проверкой результата, чтобы тесты не загрязняли production-таблицы.

## Маршруты

| URL | Статус | Назначение |
| --- | --- | --- |
| `/rating` | canonical | Ranked MMR по умолчанию, отдельно оценка практики |
| `/leaderboard` | legacy redirect | `308` на `/rating` с сохранением query string |
| `/play` | canonical | индивидуальная практика и real-shell |
| `/online` | canonical | Quick Match, Ranked и Private Battle |
| `/battle` | canonical secondary | создание приватного матча |
| `/daily` | canonical | задача дня с серверным временем сброса |

## Достижения

Все семь существующих достижений остаются: `first-run`, `perfect-five`, `streak-five`, `shell-rookie`, `daily-one`, `daily-three`, `hundred-tasks`. Они достижимы, понятны и привязаны к реально работающим событиям. Новые достижения не добавляются, данные не мигрируются.

## API compatibility

- Добавляются `practiceScore` и `practiceScoreDelta`.
- Старые `rating` и `ratingDelta` остаются в ответах на переходный период.
- Ranked ответы продолжают отдавать `mmr`; совместимый `rating` в Ranked leaderboard пока остаётся.
- Daily получает `nextResetAt` от PostgreSQL — это единственный источник времени следующего задания.

## Намеренно не меняется

- Формулы Practice score и Ranked MMR.
- Sandbox security model, WebSocket-протокол и TTL.
- Правила Quick, Ranked, Private Battle, Daily, Learn и Learning Paths.
- Существующие пользовательские результаты, прогресс, MMR и достижения.
